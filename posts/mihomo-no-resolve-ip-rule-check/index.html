Mihomo 的 IP 规则为什么会触发 DNS？用 no-resolve 做一次对照

加油2026-11-28— 次阅读
故障排查

在 Mihomo 里加了 no-resolve，运行日志还出现 DNS，或者那条 IP-CIDR 仍被命中。这两种现象都要从请求交给内核的目标和规则的先后顺序看起。

示意图。规则要按 IP 匹配时，可以用已有地址，也可能需要先解析域名。

先确认目标是名字还是地址

比如应用给内核的是一个域名。扫描到普通的目标 IP 规则时，Mihomo 可以先解析这个域名，再用得到的地址判断是否属于目标网段。如果该规则附有 no-resolve，这条规则会跳过主动发起的这一步。应用直接交给内核一个 IP，或者前面规则已经触发解析时，有地址可供判断，带 no-resolve 的目标 IP 规则仍可能命中。

用副本只改一行试验

以下是观察规则次序的片段。192.0.2.0/24 是文档示例网段，TestPolicy 与 BaselinePolicy 要替换为你已有的测试策略组，实际验证时，改用自有测试域名及其真实目标地址所属的网段。不要直接覆盖正在使用的订阅配置。

rules:
  - IP-CIDR,192.0.2.0/24,TestPolicy,no-resolve
  - MATCH,BaselinePolicy
  1. 保持客户端模式和入口相同，先查该请求进入 Mihomo 时显示的是域名还是 IP。确认列表中前面没有提前命中的域名规则。
  2. 在同一个测试副本中只移除 no-resolve，其余规则和策略组一致。用同一个测试域名发起新的连接，分别记下命中规则、目标地址是否已知，以及是否有同一时刻的 DNS 记录。
  3. 若加上后仍命中，回查更靠前的目标 IP 规则以及进入内核时已有的地址。打开旧页面可能在复用连接，应用和系统也可能提前解析。证据不足时，把该次结果记为“已有地址来源待确认”。

验收时保留两份脱敏的命中记录。能说明哪个规则先拿到或使用地址，就有足够依据决定要把域名规则、IP 规则和兜底按什么顺序摆放。
