curl 连续两次请求变快，是机场节点加速吗？先核对连接复用

用 curl 比较机场线路时，第二次请求更快，不一定是节点忽然变快。curl 官方手册说明，同一次命令里请求多个 URL 时可能复用连接，减少重新连接和握手；不同的 curl 进程之间则不能复用这条连接。先弄清测试方式，再解释时间差。

先确认是否在同一次命令里测试

选择你有权访问、可重复读取的同一个 HTTPS 页面，在 Windows PowerShell 中运行下面的示例；把示例域名换成自己的公开测试目标。-q 避免个人 curl 配置干扰，--output NUL 不保存正文，--write-out 每次传输打印新建连接数和总时间。

curl.exe -q --silent --show-error --output NUL --write-out "new=%{num_connects} total=%{time_total}\n" https://example.com/ --output NUL https://example.com/

如果第二行的 new=0，这次传输没有新建连接，不能把较短时间全部归功于线路。若第二行仍新建连接，可能是服务器关闭连接、设置不同或其他连接条件变化，不必强行解释为节点故障。

示意图：左侧可能复用同一连接；右侧独立 curl 进程各自建立连接。

比较机场时怎样留证

固定目标 URL、设备、网络、代理节点和测试时段，记录每次的 num_connects、最终 HTTP 状态与真实任务结果。若是分两次执行 curl.exe，前一次的连接不会跨进程带到后一次；两次快慢仍可能受 DNS、TLS、服务器负载或缓存影响。不要把 remote_ip 直接当作机场出口地址：它记录的是最近一次连接的远端，在使用本地代理时可能是代理端点。

验收边界

这组命令只用来识别连接是否复用，不提供机场速度排名。选购时再用你常访问的网站、相同请求和多个时段做对照，记录失败次数与实际页面能否完整加载；单次 time_total 不能代表长期稳定性。
