网站疑似解析到旧 IP？用 curl --resolve 做单次目标地址对照

网站换了服务器，电脑却偶尔访问旧页面时，先别把结果直接算到机场节点头上。curl 官方文档说明，--resolve 可在一次请求中为指定“域名:端口”提供地址，类似临时覆盖本次 DNS 结果；它不会修改系统 hosts，也不等于全网 DNS 已更新。

准备可比较的地址

从网站管理员或公开公告取得待比较的目标 IP；不要使用来历不明的“加速 IP”。确认目标域名确实由你有权测试，并记下测试时间、网络和是否启用代理。若站点使用 CDN，某个 IP 可能只代表一个边缘入口。

同一终端做两次 HTTPS 请求

先运行常规请求，例如 curl -I https://example.com/；再运行 curl --resolve example.com:443:203.0.113.10 -I https://example.com/。这里的域名和地址只是文档示例，实际替换为已核实的目标。比较状态码、证书验证结果与页面标识；不要加 -k 跳过证书校验，也不要把带账号参数的 URL 写进共享日志。若实际站点不允许 HEAD，改用同一只读页面的 GET 对照。

示意图：保持域名、端口与 HTTPS 校验不变，只比较目标地址。

如何解读差异

指定 IP 成功而常规请求失败，说明本机到两个地址的路径结果不同，下一步再查 DNS 记录和缓存。两者都失败，则不应宣称只需换 DNS。通过 HTTP/SOCKS 代理时，目标域名可能由代理端解析；--resolve 未必在目标端生效。先用直连对照弄清本机解析，再看客户端日志或代理侧证据，别把本地命令结果当作整个机场出口的结论。
