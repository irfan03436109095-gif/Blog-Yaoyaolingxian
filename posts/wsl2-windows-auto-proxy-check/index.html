Windows 浏览器能上网，WSL 2 为何不通？先查自动代理传递

加油2026-11-24— 次阅读
故障排查

Windows 浏览器可以打开网站，WSL 里的包管理器却超时。把「Windows 浏览器」「WSL 进程」当作两个观察点。若你用机场推荐的方案搭开发环境，可以先验收 Linux 工具能否拿到并使用 Windows 的 HTTP 代理信息。

确认发行版和自动代理选项

在 Windows 终端执行 wsl --list --verbose，查看出问题的发行版是否为版本 2。Microsoft 对 Windows 11 22H2 及以上的说明把 autoProxy 列在 .wslconfig 的 [wsl2] 段。这个文件位于 Windows 用户目录，现行设置文档列出的默认值为 true。如果文件里有明确设定，以实际值和设备版本为准。 WSL 网络与 Auto Proxy WSL 配置文件与选项

示意图。Windows 向 WSL 2 传递设置以后，还要验证 Linux 程序能否使用它。

在 Linux 里只检查变量是否有值

打开出问题的发行版，在与待测工具相同的 Shell 里运行下面的命令。命令只输出有值的变量名，方便保留记录时隐藏代理地址。最好先在新终端核对，再与发生故障的终端或程序环境比一遍。

for name in http_proxy https_proxy no_proxy HTTP_PROXY HTTPS_PROXY NO_PROXY WSL_PAC_URL; do
  if [ -n "$(printenv "$name")" ]; then
    printf '%s 有值\n' "$name"
  fi
done

Windows 手动代理传进来时，可看到对应的 HTTP_PROXY、HTTPS_PROXY 或小写版本。NO_PROXY 属于绕过名单。只看见 WSL_PAC_URL 时，记录 Windows 采用 PAC 的证据，再查 Linux 工具是否支持读取或求值 PAC。Microsoft 也说明，用户自行定义的变量可以优先于自动代理产生的变量。 WSL 自动代理故障排查

用同一个 URL 和同一个工具复测

  1. 在 Linux 中用一个无需登录的 HTTPS 地址做请求，记录命令、时间和错误或响应码。没有得到响应时，分辨报错是在找域名、连代理地址还是建立 TLS。如果变量指向 127.0.0.1，还要查 WSL 网络模式，默认 NAT 下的 Linux 回环地址和 Windows 主机是不同的观察点。
  2. 查看代理客户端是否记录了这次请求。变量已存在但日志找不到对应请求时，核对工具自己的代理设置、绕过列表和监听地址。先在这些线索能解释结果时再改一项设置。
  3. 如果确实需要让 WSL 重读配置，保存发行版里运行的工作，再从 Windows 执行 wsl --shutdown 并重新打开原发行版。用原来的工具和 URL 重做测试。验收记录应包含变量是否有值、原程序能否得到预期响应，以及客户端日志是否和试验时间对得上。

如果 Windows 上的两个程序也走不同路径，可接着核对 WinHTTP 与浏览器代理。 WinHTTP 显示直接访问，浏览器为何还能走机场代理？
