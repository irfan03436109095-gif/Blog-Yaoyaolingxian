WinHTTP 显示直接访问，浏览器为何还能走机场代理？

加油2026-11-23— 次阅读
故障排查

同一台 Windows 电脑，浏览器正常加载，某个更新工具却连不上。此时 netsh winhttp show proxy 可能显示「直接访问」。先弄清这条命令查询的配置，再分别查浏览器和出问题的程序。

分开看两张配置单

打开「设置 → 网络和 Internet → 代理」，记下系统的自动配置脚本和手动代理状态。也看浏览器的代理配置来源，例如使用系统设置、扩展或自身规则。记下是哪一个用户会话，以及机场客户端当前使用的模式。

在终端运行下面的只读命令。第一条显示 WinHTTP 的基础代理设置及相关绕过列表。第二条在系统支持时显示高级设置，可补充自动发现等配置线索。命令不识别时，保留第一条结果即可。

netsh winhttp show proxy
netsh winhttp show advproxy

「直接访问」说明基础 WinHTTP 设置没有列出显式代理。它覆盖的范围小于整机流量。 Microsoft Learn 的 netsh winhttp 命令

示意图。浏览器环境与 WinHTTP 的配置可能独立，两个入口要各自核对。

先查出问题的软件会读取哪一套

用软件官方说明核对它采用的网络库、代理配置方式和运行账号。WinHTTP 应用能按会话指定代理，部分设置也能按请求覆盖。后台服务使用的账户和你打开浏览器的账户可能不同。客户端如果使用 TUN，路由还可能在应用代理选择之后接管流量。仅凭设置页和 netsh 输出都无法确认某次请求的实际出口。 Microsoft Learn 的 WinHTTP 代理会话与请求说明

用一个可重复的动作确认范围

  1. 选问题程序里的一个无副作用动作，例如查看更新信息。记录时间、目标域名和报错，避免反复触发下载安装。
  2. 在相同网络与客户端模式下，检查客户端连接记录里有没有该动作对应的目标。查不到记录时，同时看应用日志是否显示代理连接、解析或超时错误。
  3. 若应用允许临时使用明确的代理配置，可在自己的设备上按厂商说明单独验证该应用。测试后恢复原设置。企业设备先按管理员给出的范围操作。

基于机场推荐做试用时，最好把「浏览器网页成功」和「目标应用任务成功」写成两项。这样一条线路能满足哪些工作场景，有实际任务结果可核对。
