网卡 LinkSpeed 很高，为什么下载仍慢？先分清本地链路与端到端吞吐

加油2026-10-10— 次阅读
客户端教程

Windows 显示的网卡链路速度，与从某个网站下载文件的速度，描述的不是同一段过程。一个本地属性很高，不会自动证明宽带、机场路径和目标服务器都能达到同样吞吐。

本文用于查看自己的 Windows 电脑，先读取属性，不更改驱动、双工模式、网卡绑定或路由。单位设备遵守已有管理要求。

示意图：本地链路属性只是环境一项，下载表现需要独立验收。

先确认看的到底是哪张网卡

微软 Get-NetAdapter 文档说明，它读取网络适配器基本属性，默认返回可见适配器。可以先用下面的只读命令整理列表：

Get-NetAdapter | Select-Object Name, InterfaceDescription, Status, LinkSpeed
Get-NetAdapter -Physical | Select-Object Name, InterfaceDescription, Status, LinkSpeed

第一轮帮助辨认列表，第二轮缩小到物理适配器。网卡名称以本机输出为准，不假定必叫 Wi-Fi 或 Ethernet。把时间、名称、描述、状态和 LinkSpeed 记下来即可，无需公开 MAC 地址。

微软的性能历史示例也将网卡 LinkSpeed 属性与观测到的带宽分别处理。这里借用的是属性含义，不要求个人电脑运行集群工具。

三类数字分开读

数字或状态 所描述的对象
物理网卡的 LinkSpeed 本地接口报告的链路属性
虚拟适配器显示的数值 相应虚拟接口的属性
下载工具实际收到的字节与用时 当次端到端任务的观察

看到虚拟适配器的高数值，不能据此宣布无线链路或机场更快。多个适配器同时显示连接状态，也不能仅靠这张列表确认某个应用实际走了哪条路。

下载慢时按范围核对

  1. 保存本地属性。 先明确当前使用有线还是无线，识别对应接口；不凭数值大小挑一张网卡当作依据。
  2. 保存下载条件。 目标文件、大小、工具限速、并行任务、代理模式和节点分别记录。小文件瞬间完成不适合估计持续吞吐。
  3. 安排一轮有限任务。 使用允许访问且大小已知的资源，记录是否完成、实际字节和用时，而非只截瞬时峰值。
  4. 需要比较时只改一项。 例如同一资源和工具下比较已有的两种本地接入，或比较节点；两类比较分开做，避免一轮同时改变全部环境。

如果本地属性发生变化而任务也变化，可以记录关联线索；仍需排除其他条件。不要为了提高显示数字，随意强制设备不支持的模式。

怎样算记录足够清楚

读者能区分哪个数字来自接口、哪个来自真实任务，并知道测试路径和时间，就能复查这次判断。单位也要原样记清：位每秒与字节每秒不能直接当作同一数值。

整理机场推荐时，LinkSpeed 可作为环境说明。最终是否满足需要，应由目标任务是否完成、持续表现和条件限制共同说明，不能把一张网卡属性表改写成服务商性能承诺。
