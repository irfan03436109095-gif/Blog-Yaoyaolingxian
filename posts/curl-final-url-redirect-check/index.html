机场测速返回 200 却打开登录页？核对最终 URL 与跳转次数

王牌飞行员2026-10-04— 次阅读
故障排查

下载测试文件时看到 HTTP 200，打开保存文件却是登录界面，这次不能计为目标下载成功。状态码说明收到响应，最终网址与实际内容才说明测到了什么。

示意图：200 是最后一次响应的状态，仍需确认它是不是想测的资源。

什么时候需要这项检查

适用于公开测试资源发生跳转、公共网络门户干扰、网站要求登录，或两次测速内容大小明显不同的情况。它不用于把含订阅令牌、Cookie 或登录凭据的请求自动跟随到未知地址。

先用浏览器确认预期资源的位置及用途，再选择自己有权访问的公开 URL。涉及机场推荐的对照测试，优先采用内容固定、体积适中的资源。

先看原响应，再决定是否跟随

Windows PowerShell 中将公开目标填入变量，先不自动跟随跳转：

$testUrl = 'https://example.com/'
curl.exe -q --silent --show-error --connect-timeout 10 --max-time 30 --dump-header initial-headers.txt --output initial-body.txt $testUrl
$LASTEXITCODE

示例网址用于说明语法，不是测速文件。查看响应头中的状态和 Location，核对跳转域名是否符合预期。不要在这里粘贴含私有令牌的订阅地址。

对确认可以跟随的无凭据公开目标，再运行：

curl.exe -q --silent --show-error --location --max-redirs 5 --proto-redir '=https' --connect-timeout 10 --max-time 30 --output result-body.txt --write-out 'status=%{http_code}
final=%{url_effective}
redirects=%{num_redirects}
type=%{content_type}
' $testUrl
$LASTEXITCODE

这里限制跟随次数和跳转协议，并保持 HTTPS 验证。curl 官方资料说明 --location 用于跟随跳转，url_effective 是最后取得资源的网址；不要用 --location-trusted 把凭据继续传到别处。

四项一起验收

  1. 程序退出码：传输有没有发生错误。
  2. HTTP 状态：是否是当前任务预期的响应。
  3. 最终 URL：域名和路径是否仍属于预期资源，而不是门户或登录页。
  4. 正文：内容类型与实际文件是否符合预期，不能只看扩展名。

最终 URL 含个人信息时，只在私下记录，公开分享要脱敏。内容类型也是线索而非绝对证明；服务器可能标错，因此仍要检查文件本身。

怎样放进对照记录

记录每轮节点、时间、最终路径、跳转次数、内容检查结果及耗时。只有任务到达预期资源、正文通过核对，才计为这一轮成功。目标本身增加了跳转时，保留变更，不把耗时差全部归因于机场线路。
