电脑同时连 Wi-Fi 和网线，curl 怎么固定出口做对照？

王牌飞行员2026-10-01— 次阅读
故障排查

笔记本同时连着 Wi‑Fi 和网线时，即使机场节点没变，两次测试也可能走不同的本地出口。若不固定接口，看到的速度差、丢包或连接时间未必来自节点。curl 的 --interface 可以把请求绑定到指定接口或本地地址，用来做可复查的路径对照。

先确认接口名称与地址

Windows 可用 Get-NetIPConfiguration，macOS 与 Linux 可用 ifconfig 或 ip addr 查看接口。先确认哪一个是 Wi‑Fi、哪一个是有线网卡，并记录各自本地地址、默认网关和 DNS。不要照抄别人电脑上的 eth0，接口名称因系统而异。

curl 官方手册允许 --interface 指定接口名、本地 IP，或使用带类型前缀的写法。基础示例是：

curl --interface eth0 https://example.com/

在支持的环境中，也可以绑定明确的本地地址。若命令返回退出码 45，表示指定的出口接口无法使用，应先修正接口名或权限，而不是把它当成机场节点故障。

做一组公平对照

选择一个小而稳定的 HTTPS 地址，先通过 Wi‑Fi 连续请求五次，再通过网线请求五次。更公平的顺序是 Wi‑Fi、网线、网线、Wi‑Fi 交替执行。记录远端地址、连接耗时、首字节耗时、总耗时和退出码。

命令示例：

curl --interface "接口名" --silent --output /dev/null \
  --write-out "remote=%{remote_ip} connect=%{time_connect} start=%{time_starttransfer} total=%{time_total}\n" \
  https://example.com/

如果本机还运行 TUN 模式代理，绑定物理接口不一定等于绕过代理。应同时查看客户端路由日志或出口 IP，确认请求到底经过哪条链路。

结果怎么读

若 Wi‑Fi 的连接时间波动大，而网线稳定，先检查无线信号、信道与省电设置。若两种本地接口都在同一节点、同一时间出现相似的首字节升高，更可能是上游路径或目标站负载。若远端 IP 不同，说明 DNS、双栈选择或 CDN 入口也发生了变化，不能直接比较总耗时。

验收标准

确认两组命令都成功、证书验证开启、目标 URL 相同，并保留接口名和测试时刻。交换测试顺序后结论仍一致，才能说明差异与本地出口有关。若只有一次最快值不同，证据不足。

这套方法适合在机场推荐测试前排除本地接入差异，也适合定位“插上网线反而更慢”这类问题。
